# 天凤牌谱分析 v0.1.0

把天凤（tenhou.net）的 `.xml` 牌谱在本地解析成「逐帧状态」，打点出 **33 个牌谱特征**存进 SQLite 数据库，
再用网页回放牌局、按特征检索局面、把当前帧的全部特征值并排显示。全部在本机运行（只有「牌谱下载」会联网）。

- 前端：`web/index.html` + `web/js/`（原生 JS，无框架、无构建步骤）
- 后端：`mjscore/`（Python 标准库）+ 可选的 Node.js 打点
- 数据库：SQLite，默认放在 `data/db/`

---

## 1. 功能

| 页签 | 能做什么 |
| --- | --- |
| **首页 / 播放** | 选择本地牌谱或载入示例 → 牌桌、牌河、副露、和了信息、事件列表（点击跳帧）。键盘：`←/→` 上一帧 / 下一帧，`↑/↓` 上一事件 / 下一事件，`Home/End` 首帧 / 末帧，`PgUp/PgDn` 上一局 / 下一局。可以隐藏他家手牌、复制当前帧的特征串 |
| **牌谱分析** | 填牌谱目录 → 扫描 → 勾选 `.xml` → **新建数据库**（填库名）或 **扩充现有数据库**（从下拉选已有库）→ 进度条实时显示「已完成 x / y 个牌谱 ｜ 当前 <特征码> ｜ 局 a/b ｜ 耗时」 |
| **牌谱检索** | 先选本地数据库文件，再逐条添加「牌谱特征」条件（同一条特征不能重复添加）→「检索」返回所有满足全部条件的打点帧，「全部浏览」按顺序翻阅。点击条目跳到对应帧，右侧列出当前帧的 **33 个特征**（检索用到的条目高亮） |
| **牌谱下载** | 输入单个完整 url，或选一个「每行一个 url」的文本文件 → 指定本地存储地址（默认 `data/paipu/<时间戳>`）→ 下载、同名覆盖，界面显示待下载 / 成功 / 失败数量 |

界面右上角显示版本号（`v0.1.0`），数据库里也记录生成它的软件版本（见第 5 节）。

### 1.1 检索条件的写法

- 互斥取值的特征（局况、是否南三局及以后、自家、自家立直状态、自家副露状态、亲家（他家）立直状态、亲家（他家）副露状态）用**下拉框**选择。
- 整数 / 实数特征用文本框，支持四种写法：

| 写法 | 含义 |
| --- | --- |
| `3` | 等于 3 |
| `1-30` | 区间（含两端） |
| `1,2,3` | 列表（任意一个即可） |
| `>=3` | 比较（`>` `>=` `<` `<=` 都行，实数如 `>=0.5` 也可以） |

多个条件之间是 **AND**：每个条件都要同时满足，所以条件越多结果越少。先用「全部浏览」确认库里有数据，再逐步加条件。

三种**向听数**特征比较特殊：内部取值是整数 `-1 / 0 / 1 / 2 / 3`（`3` 表示「>=3 向听」），
界面与本文档把它**显示**成 `>=3`，但**检索时仍按内部整数匹配** —— 填 `3`、`3-5`、`>=3`
都会命中内部值为 3 的帧（`>=3` 只是展示口径，不改变匹配逻辑）。

## 2. 33 个特征

### 2.1 第一类特征（16 个，逐帧的几何 / 局势信息）

| 特征名 | 取值 |
| --- | --- |
| 局况 | 東一局 … 北四局（16 种） |
| 是否南三局及以后 | 是 / 否 |
| 巡目 | 1 ~ 30（按「出牌」计：吃/碰/大明杠不增加，暗杠/加杠算出牌一次） |
| 供托 | 0 ~ 30000（立直棒 ×1000 + 本场 ×300） |
| 自家 | 亲家 / 子家 |
| 顺位 | 1 ~ 4（同分按自风） |
| 自家立直状态 | 是 / 否 |
| 自家副露状态 | 是 / 否 |
| 自家副露数量 | 0 ~ 4（吃/碰/加杠/大明杠/暗杠组数；拔北不计） |
| 立直家（他家）数量 | 0 ~ 3 |
| 副露家（他家）数量 | 0 ~ 3 |
| 两副露以上（他家）数量 | 0 ~ 3 |
| 三副露以上（他家）数量 | 0 ~ 3 |
| 亲家（他家）立直状态 | 是 / 否 |
| 亲家（他家）副露状态 | 是 / 否 |
| 亲家（他家）副露数量 | 0 ~ 4 |

### 2.2 第二类特征（17 个，需要算法）

**三种向听数**（国士無双 / 七対子 / 面子手）：`-1` = 已和牌，`0` = 未和牌但听牌，`1` / `2` / `>=3`。
内部取值为整数 `-1 / 0 / 1 / 2 / 3`（`3` = 「还差 3 次以上」），界面与文档统一显示成 `>=3`；
检索条件仍按内部整数匹配（见 1.1）。
定义：为达到听牌状态，最少还要摸进或副露的牌张数。计算时会扣掉「场上已经看得见的牌」，所以不会出现期待第 5 张的胡想。

**六个期望听牌枚数**（副露自摸 / 副露荣和 / 立直·默听，各分「期望枚数」与「绝对枚数」）：非负实数，已和牌的帧记 0。
「期望枚数」= 在「达到听牌」的前提下，能达成满足起和役的和牌的牌张数的期望；「绝对枚数」不看场上可见牌，只数自身手牌能和的张数。
「立直·默听」两项对门清帧计算，副露帧为 0；带「副露」字样的四项即使当前是门清手牌也按副露状态（起和役与番数）计算。

**六个期望打点**（副露荣和 / 副露自摸 / 立直荣和 / 立直自摸 / 默听荣和 / 默听自摸）：正实数，已和牌的帧记该手牌的实际和牌得点。
「立直」= 假想保持门清直到听牌并在听牌时宣布立直（已经宣布立直时用实际的番数）；「默听」= 假想不宣布立直。副露帧的立直项为 0。
计算按天凤段位战规则（含本场 / 供托 / 宝牌，不含一发、里宝、槍槓、嶺上、海底、河底等偶发与特殊役）。

**两个危险特征**（以当前摸牌者为主视角）：其他家无人立直时为 `-1`。
- 立直家（他家）危险筋组数量：0 ~ 18
- 立直家（他家）危险两面组数：0 ~ 288

（每个特征的精确定义、口径与验证过程都写在 `log.md` 的第 11 / 13 / 14 节。）

## 3. 安装（Windows 10 / 11，从零开始）

### 3.1 需要什么

| 需要 | 说明 |
| --- | --- |
| **Python 3.8+**（推荐 3.10 及以上） | 必需。**不需要任何第三方包**，只用 Python 标准库 |
| **Node.js 18+**（可选） | 装了打点更快（`node` 跑前端同一份 JS 解析器）；不装也行，全部特征由 python 打点 |
| 浏览器 | Edge / Chrome 等现代浏览器 |
| 硬盘 | 数据库会占空间：勾选「写入原始数据」时约为每个打点帧 200~400 字节（33k 帧的库约 35 MB～） |

### 3.2 安装 Python

1. 打开 <https://www.python.org/downloads/windows/>，下载 64-bit 安装包。
2. 运行安装包，**务必勾选「Add python.exe to PATH」**，再点 *Install Now*。
3. 验证：按 `Win+R` → 输入 `cmd` 回车 → 输入

   ```
   python --version
   ```

   能打印 `Python 3.x.y` 即可（如果提示「不是内部或外部命令」，重装并确认勾选了 PATH；用 Anaconda 的话请改用 *Anaconda Prompt*）。

### 3.3 安装 Node.js（可跳过）

1. 打开 <https://nodejs.org/>，下载 LTS 版，一路「下一步」（同样保持 PATH 勾选）。
2. 验证：`node -v`。
3. 装在非默认位置时，程序会按这个顺序找 node：环境变量 `MJSCORE_NODE` → `C:\Program Files\nodejs\node.exe` → `D:\Program Files\nodejs\node.exe` → `D:\Program Files (x86)\nodejs\node.exe` → `PATH`。
   例如：`set MJSCORE_NODE=D:\tools\nodejs\node.exe`

### 3.4 准备项目

把整个项目文件夹放到任意目录（尽量别用中文路径和空格），例如：

```
D:\tools\tenhou-paipu-analysis
```

### 3.5 启动

在项目根目录打开 PowerShell（文件资源管理器地址栏输入 `powershell` 回车），然后：

```powershell
cd D:\tools\tenhou-paipu-analysis
python server.py
```

看到 `http://127.0.0.1:8770/` 后，用浏览器打开它。

> **不要直接双击 `web/index.html`**：`file://` 下浏览器不允许访问本地接口，「牌谱分析」「牌谱检索」都用不了。
>
> 端口被占用时：`python server.py --port 9000`，然后打开 `http://127.0.0.1:9000/`。
>
> 关闭服务：在 PowerShell 窗口按 `Ctrl+C`。

## 4. 使用流程

### 4.1 准备牌谱（`data/paipu/…`）

两种来源，效果一样，下载/保存到哪都行，分析时填那个目录即可。

**a) 网页「牌谱下载」**

1. 打开「牌谱下载」页签，选择输入方式：单个 url，或一个「每行一个 url」的文本文件（`#` 开头的行会被忽略）。
2. 指定本地存储地址：默认 `data/paipu/<时间戳>`（如 `data/paipu/20261007-165558`）；`data/paipu` 是固定的根目录，只有最后一段子目录名可以自定义。
3. 点「下载」，界面会显示待下载数量与成功 / 失败数量；同名文件直接覆盖。

**b) 命令行**

```powershell
python tools/download_tenhou.py http://tenhou.net/0/?log=2026082919gm-00a9-0000-4e40cd3e&tw=0
python tools/download_tenhou.py --url-file tenhou-url.txt -o data\paipu\20261007-165558
python tools/download_tenhou.py 2026082919gm-00a9-0000-4e40cd3e --no-overwrite
```

支持三种输入：完整 url、`http://tenhou.net/0/log/?<特征码>` 形式、裸特征码（`2026082919gm-00a9-0000-4e40cd3e`）。文件名就是特征码 + `.xml`。

### 4.2 分析入库

1. 打开「牌谱分析」，填**牌谱目录**（如 `data/paipu/20261007-165558`），点「扫描」。
2. 在列表里勾选要分析的牌谱（可「全选 / 全不选」）。
3. 选数据库：
   - **新建数据库**：填数据库名（默认 `paipu`）→ 生成 `data\db\<名字>.sqlite`（已存在则覆盖该库自己的记录，不删其它库）。
   - **扩充现有数据库**：从下拉框选一个已有库（显示 `名字（N 行 · v0.1.0）`）。本次分析结果会**追加**进这个库；**特征码相同的牌谱自动跳过**，不会重复写。数据库里记录着生成它的软件版本，**版本不一致的库在下拉框里标 ⚠ 且不可选**。
   - 两个入口互斥：选「扩充」时数据库名输入框会被禁用。
4. 需要的话勾选「**同时写入原始数据（--full）**」（见 5.3）。
5. 点「分析」，进度条会显示已完成 / 总数、当前正在分析的牌谱特征码、局进度与耗时；完成后提示「完成：N 个牌谱 / M 局 / 打点 K 行（库内共 …）」以及扩充时跳过几个牌谱。

分析速度参考（本机实测）：5 个牌谱（2786 个打点帧）全新分析约 11 分钟；71 个牌谱（37254 个打点帧）量级为数小时。
**建议分批分析并用「扩充现有数据库」逐步累积**，每个批次随时可用。

### 4.3 检索与浏览

1. 打开「牌谱检索」，在「本地数据库文件」下拉里选库（下拉会显示行数与版本），或直接填路径。
2. 从「牌谱特征」下拉里挑一个特征 →「添加」→ 填 / 选条件（写法见 1.1）。不想要的行点「删除」，「清空」清掉全部条件。
3. 「检索」：返回所有满足全部条件的打点帧（列表顶部显示总条数）。「全部浏览」：按顺序翻阅整库。
4. 点任意条目 → 跳到该帧；右侧「当前帧」面板列出 **33 个特征名 = 取值**，其中当前检索用到的条目会高亮；顶部显示「当前帧的特征串」（牌谱特征码 + 局况 + 本场 + 巡目 + 风位，点一下可复制）。
5. 「上一条目 / 下一条目」在检索结果之间切换，「上一条目/下一条目」与帧导航按钮都在牌桌下方。

> 只有「非自摸的摸牌帧」与「吃 / 碰 后等待出牌的帧」才有特征值；其它帧（摸牌后马上自摸、以及杠后的岭上帧等）面板里会说明没有对应的打点行。

### 4.4 回放

首页选择 `.xml` 文件（或「载入示例」），或用「牌谱分析 / 检索」跳到某个帧。播放视图支持：

- 牌桌：手牌、副露、牌河、宝牌指示牌、供托、各家分数 / 风位、和了信息（役种 / 符 / 番 / 得点）。
- 事件列表：点击任意一行跳到那一帧。
- 键盘：`←/→` 帧、`↑/↓` 事件、`Home/End` 首末帧、`PgUp/PgDn` 换局。

## 5. 数据库

### 5.1 位置与结构

- 默认路径：`data\db\<数据库名>.sqlite`（数据库名默认 `paipu`）。
- 表：
  - `meta`：库级信息（`schema_version` 结构版本、`app_version` 生成它的软件版本、行数 / 牌谱数 / 局数、创建与更新时间、是否写入原始数据等）
  - `feature_def`：33 个特征的定义（名字 / 类型 / 取值域）
  - `source`：已入库牌谱（**按特征码 log_id 唯一**）→ 扩充时的判重依据
  - `round` / `frame`：逐局、逐打点帧的定位信息与 33 个特征值
  - `frame_full`：勾选「写入原始数据」时才有内容（逐帧的手牌 / 副露 / 宝牌 / 分数）

### 5.2 版本匹配规则

| 情况 | 结果 |
| --- | --- |
| 结构版本（`schema_version`）与当前软件不同 | 拒绝加载 / 扩充，提示「请删除后重新分析」 |
| `app_version` 与当前软件不同 | 拒绝加载 / 扩充（数据库格式可能已变），提示改用原版本软件或删除后重新分析 |
| 没有 `app_version` 记录（v0.1.0 之前建的库） | 按兼容处理，可以加载 / 扩充 |

删除一个库：`python tools/analyze.py --delete-db <数据库名>`。

### 5.3 「同时写入原始数据（--full）」勾选与不勾选

- **勾选**：除 33 个特征值外，还把该帧的原始数据（手牌 / 副露 / 宝牌指示牌 / 分数 / 牌谱路径）写进 `frame_full` 表。以后新增特征时，可以只按这些原始数据重算，**不必重新解析 XML**；代价是数据库约大一倍、写库略慢。
- **不勾选**：只写 33 个特征值与定位信息，库更小、写库更快；但**以后新增特征只能重新分析全部牌谱**。

### 5.4 为什么「扩充」会跳过牌谱

`source` 表以**牌谱特征码（log_id）**为主键记录已经入库的牌谱，扩充时按它判重：已经有的直接跳过，不会重复写入。
所以即使不先自己判重，也可以放心地重复把同一个目录拿去「扩充」。整批都是旧牌谱时会直接提示「这 N 个牌谱都已经在数据库里了」。

### 5.5 移动牌谱文件

移动 / 重命名 `data/paipu/...` 下的牌谱**不影响已有数据库**：检索、回放、特征面板都只读数据库。
`frame_full` 里记录的源路径只是备注；下一次分析填新的目录即可。

## 6. 命令行速查

```powershell
# 分析：牌谱文件或目录（目录会递归找 .xml），可多个
python tools/analyze.py data\paipu\20261007-165558 --db-name paipu --full
python tools/analyze.py data\paipu\20261007-165558 --db-name paipu --extend   # 只分析库里还没有的牌谱
python tools/analyze.py <目录> --tool python          # 强制用 python 打点（不依赖 node）

python tools/analyze.py --list-dbs                    # 列出 data/db 下的库（含行数与软件版本）
python tools/analyze.py --features                    # 打印 33 个特征定义
python tools/analyze.py --query < 条件.txt            # 每行「特征名=条件」，例如「面子手向听数=0」
python tools/analyze.py --db-name paipu --values 面子手向听数
python tools/analyze.py --db-name paipu --export out.json
python tools/analyze.py --delete-db paipu
python tools/analyze.py --version                     # 天凤牌谱分析 v0.1.0

python server.py [--port 8770]
python tools/download_tenhou.py <url>... [-f 文件] [-o 目录] [--no-overwrite]

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面提示「连不上本地服务」 | 先在项目根目录运行 `python server.py`，再用它打印的 `http://127.0.0.1:8770/` 打开（不要用 `file://`） |
| 分析很慢 | 打点本身比较重（尤其第二类特征）。可以先只分析一小批，用「扩充现有数据库」慢慢累积；机器上装了 node 会自动用 node 打第一类特征 |
| 提示找不到 node | 只影响速度，程序会自动全部改用 python。想用 node 就安装 Node.js，或 `set MJSCORE_NODE=...\node.exe` |
| 提示「数据库由软件版本 X 生成」 | 用建库时的软件版本打开，或 `python tools/analyze.py --delete-db <库名>` 后重新分析 |
| 检索结果很少 / 没有 | 条件之间是 AND，越多越少；先「全部浏览」确认库里有数据，再逐个加条件 |
| 端口 8770 被占用 | `python server.py --port 9000` |
| 忘记库名 / 有哪些库 | `python tools/analyze.py --list-dbs`，或看 `data\db\` 目录 |
| 想换打点工具 | 不用换：默认自动（第一类走 node、第二类由 python 补齐），两种结果逐字段一致 |

## 8. 依赖、目录与版本

- **运行依赖**：Python 标准库（`http.server` / `sqlite3` / `urllib` / `xml.etree` / `json` 等）；可选 Node.js（只用内置模块）。**没有 pip / npm 第三方包**，不需要联网安装。
- **目录**

  ```
  server.py    启动本地服务（前端页面 + /api 接口）
  web/         前端：index.html、style.css、js/（牌谱解析 / 回放 / 特征 / 界面）
  tools/       命令行工具：analyze.py（分析 / 检索 / 导出）、download_tenhou.py（牌谱下载）
  mjscore/     后端：mjlog、replay、feats、agari（和牌与点数）、shanten（向听）、
               expect（期望枚数 / 打点）、danger（危险筋组）、store、cli、server、download
  data/paipu/    牌谱（下载默认写这里）
  data/db/       SQLite 数据库

## 9. 打包发布（Windows，可选）

普通用户不需要这一节；只有要把项目打成安装包（分发用）时才用到。

**准备**：`D:\coding\anaconda3\envs\py314_null` 里装好 PyInstaller（`python -m pip install pyinstaller`，要 >= 6.19 才支持 Python 3.14）；在项目根执行一次 `npm install`（Electron + electron-builder，首次会下载约 100 MB）。

**一键打包**（在项目根、用普通（非受限）终端）：

    powershell -ExecutionPolicy Bypass -File .\build.ps1

脚本依次做：检查环境 → 清理（`-Clean`）→ 生成图标（`media\tiles\6m.svg` → `build\icon.ico`）→ 跑回归（`test\apptest.js`）→ 用 PyInstaller 把后端打成 `dist\pyi\tenhou-paipu-analysis-server\`（onedir，内嵌 `node.exe`）→ 冒烟测试（`-Smoke`）→ electron-builder 打 NSIS 安装包到 `dist\electron\`。

常用开关：`-SkipIcon`、`-SkipTests`、`-FullTests`（加跑需要真实数据目录的 `test\datamgr_test.py`）、`-SkipPyi`、`-SkipElectron`、`-Clean`、`-Smoke -Port 8788`、`-PythonExe <路径>`、`-NodeExe <路径>`。也可以 `npm run build` / `npm run dist`。

**产物**：`dist\electron\tenhou-paipu-analysis-0.1.0-setup.exe`（NSIS，安装路径可选）。安装后：

- 程序装在自选目录（默认当前用户 `%LOCALAPPDATA%\Programs\tenhou-paipu-analysis`）；
- 后端与 Node 在 `<安装目录>\resources\backend\`；
- 牌谱与数据库固定放 `%LOCALAPPDATA%\tenhou-paipu-analysis\data\{paipu,db}`（界面「本地数据管理」页签里管理）；
- 卸载时会询问是否一并删除上面这个数据目录（默认保留）。

**注意**

- PyInstaller 的参数只有一份，写在 `packaging\pyi_build.py`（它会打印等价命令）；受限终端里若 hook 发现报 `PermissionError [WinError 5] / create_pipe`，`build.ps1` 会自动加 `--in-process` 兜底。
- electron-builder 需要能用匿名管道启动子进程（`npm`、`makensis`）；日志里若出现 `spawn EPERM` / `EPERM: operation not permitted`，换普通终端重跑。
- 目前没有代码签名，安装时 SmartScreen 会提示「未知发布者」。
- 只支持 Windows x64。图标可由 `tools\svg2ico.py` 从素材复现，不需要外部图片。
