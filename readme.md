# 天凤牌谱分析 v1.4.4

把立直麻将牌谱变成**可检索的数据**：对天凤牌谱（`.tenhou`）、NAGA 报告（`.naga`）、Mortal 报告（`.mortal-a` / `.mortal-b` / `.mortal-c`）逐帧标注 **42 个牌谱特征**，写入本机 SQLite 数据库；之后就能按特征把「想找的那一手」从成千上万个决策帧里检索出来。牌谱回放按天凤风格绘制牌桌，并可叠加 NAGA / Mortal 的 AI 决策概率。

所有计算都在本机完成：服务只监听 `127.0.0.1`，牌谱与数据库都保存在本机，不联网、不上传。

## 1. 功能一览

| 页面 | 用途 |
| --- | --- |
| 牌谱下载 | 用单个 URL 或「每行一个 URL」的文本文件，把牌谱批量下载到 `data/paipu/` |
| 牌谱播放 | 天凤风格的牌桌回放；NAGA / Mortal 报告可叠加 AI 决策概率与决策表 |

## 3. 名词与约定

**决策帧（打点帧）**：分析只给下面三类帧打点，其它帧（摸牌后马上自摸、杠后的岭上帧等）不写入数据库。

| 帧 | 含义 |
| --- | --- |
| 摸牌帧 | 摸到牌之后要决定打哪一张（摸牌后马上自摸的除外） |
| 吃 / 碰后帧 | 吃或碰之后要决定打哪一张 |
| 鸣牌响应帧 | 有人打出一张牌、而这张牌可能被他家鸣牌；此时每个「可能鸣牌」的家各算一个决策帧 |

**视角与称呼**：视角 = 这一帧的决策者。「自家」= 当前决策者，「他家」= 另外三家。每行数据都站在该帧决策者的角度记录。

**巡目**：自家出牌次数 + 1。摸牌不增加巡目；吃、碰、大明杠不算出牌；暗杠、加杠算一次出牌。

**供托**：立直棒 ×1000 + 本场 ×300，折算成点数。

**牌谱特征码**：牌谱文件名去掉后缀（如 `2026082919gm-00a9-0000-4e40cd3e`），播放、检索、数据库里都用它标识同一份牌谱。

**向听数**：国士無双 / 七対子 / 面子手三种，取值 `-1`（已和牌）、`0`（听牌）、`1`、`2`、`>=3`（还差 3 次以上）。界面与文档里 `3` 一律显示成 `>=3`，检索时按 `>=3` 填。

**牌谱文件后缀**：天凤 `.tenhou`；NAGA `.naga`；Mortal `.mortal-a`（避四）/ `.mortal-b`（平衡）/ `.mortal-c`（争一）。旧后缀 `.xml`、`.mjlog`、`.json.gz`、`.json` 也认。

## 4. 牌谱下载

进入「牌谱下载」页，可以直接输入**单个牌谱 URL**（或裸特征码），也可以选择**本地文本文件**（每行一个 URL）批量下载。

支持三种来源：

| 来源 | 输入什么 | 落盘后缀 |
| --- | --- | --- |
| 天凤 | 天凤牌谱 URL（`tenhou.net/0/?log=…`），或裸特征码 | `.tenhou` |
| NAGA | 官方观看页 URL（`naga.dmv.nico/htmls/report_viewer.html?report_id=…`）或 ricochet 代理 URL | `.naga` |
| Mortal | 报告 URL（`mjai.ekyu.moe/report/<16 位十六进制>.json`） | `.mortal-a` / `.mortal-b` / `.mortal-c` |

- 存储子目录固定为 `data/paipu/<子目录>`，子目录名可自定义（点「用当前时间戳」生成一个）。
- 本地已存在同名文件时：天凤、NAGA 官方、Mortal 来源**直接跳过**（想重下先删本地文件）；ricochet 代理来源**重新下载并覆盖**。
- 下载完成后，「牌谱分析」页的目录下拉会自动跟到刚才的目录。

## 5. 牌谱播放

### 5.1 打开牌谱

三种方式，互不冲突：

- **浏览选择**：选择本地牌谱文件（天凤 `.tenhou` / NAGA `.naga` / Mortal `.mortal-a|b|c`，旧后缀也认）。
- **按特征码搜索**：输入特征码的**连续片段**（如 `2026082919gm` 或 `60b5c2ad…v2_2`），在已下载的牌谱里搜索；结果里匹配到的子串会高亮，点击直接进入播放。
- **拖放**：把牌谱文件拖到牌桌区域。

工具栏还会显示当前文件的特征码、`局` 下拉、第几帧 / 共几帧，并提供「复制url」（天凤谱复制天凤牌谱页，NAGA 谱复制官方观看页）。

### 5.2 控制面板

| 按钮 | 作用 |
| --- | --- |
| ⇤ 上一局 / 下一局 ⇥ | 跳到上一局 / 下一局的开头 |
| ‖◀ 开局 / ‖▶ 完场 | 跳到整份牌谱的第一帧 / 最后一帧；「完场」再点一次会弹出最终顺位结算框（1 位 … 4 位与最终点数） |
| \|◀ 本局开始 / 本局结算 \|▶ | 跳到本局的第一帧 / 最后一帧 |
| ◀◀ 上一决策 / 下一决策 ▶▶ | 停在**任何一个需要某家做决策的帧**（摸牌、吃 / 碰、鸣牌响应） |
| ◀◀◀ 上一自家决策 / 下一自家决策 ▶▶▶ | 只停在**主视角本人**需要决策的帧 |
| ◀ 上一步 / 下一步 ▶ | 逐帧前进 / 后退（包含不需要决策的展示帧） |
| 切换主视角 | 从四家（按东 1 局座次）里挑一家；牌桌、概率条、决策表都会跟着换到那个视角 |
| 隐藏他家手牌 | 盖住另外三家的手牌（AI 概率条与决策表同时隐藏）；静态帧里此按钮不可用 |

帧计数右侧的「局」下拉可以在局之间直接跳转。

### 5.3 牌桌上的标记

| 标记 | 含义 |
| --- | --- |
| 红框（牌河） | 这张牌被鸣走了（吃 / 碰 / 大明杠） |
| 绿框 | 荣和时放铳的那张牌（也在和了家的手牌里标出和了张） |
| 细红框（手牌） | 当前决策者下一步要打出的那张牌；如果下一步是**暗杠 / 加杠**，则把准备杠的 4 张全部框出（暗杠 = 手里 4 张，加杠 = 手里 1 张 + 副露区 3 张） |
| 黄框 | 在**检索结果的静态帧**里，标出「鸣牌响应局面」中那张被响应（等待决定吃 / 碰 / 杠 / 过）的打出牌 |
| 半透明牌 | 摸切（摸到就打） |
| 横放牌 | 副露里被鸣走的那张；加杠时第 4 张叠在它正上方 |
| 日语大字 | チー / ポン / カン / ロン / ツモ，按官方位置与字号显示 |
| 听牌率条 | 手牌旁的竖条：从下往上按听牌率变红（四种花色基色按视角定色） |
| 紫色概率柱 | 该张牌的 AI 打牌概率（只画当前决策者的那一档）；新版 NAGA（`NAGA-避四` / `NAGA-争一`）如果这张牌既能默听打又能立直打，柱子会从中间一分为二：**左半紫 = 默听打这张牌的概率、右半红 = 立直打这张牌的概率**，两半高度各自独立；只出现在立直支的牌画整宽红条；默听条一律同一紫色 `rgb(124, 59, 230)`、立直条一律同一红色 `#e0503a`，不再对「概率最高的那张牌」单独高亮（用户 m10014） |
| 放铳率条 | 打出该张牌的放铳率 |

### 5.4 AI 决策面板（右侧）

只有 NAGA / Mortal 报告带 AI 决策数据，天凤牌谱这一栏留空。

- **标题按钮 = 模型下拉**：可选「无AI决策」（默认，等于天凤牌谱的展示方式）、`NAGA-平衡 决策`、`NAGA-超副露 决策`、`NAGA-避四 决策`、`NAGA-争一 决策`、`Mortal-4.1-平衡 决策` 等；报告里没有的模型灰显不可点。选择会被记住：切到别的帧时，如果那一帧没有该模型的数据，会临时显示「无AI决策」，有数据时自动切回。
- **当前决策**：这一帧由谁做决策。
- **决策选项表**（**只是这一列的显示开关**，与 4.4 里的「决策帧 / 关键帧」判定无关 —— 播放导航与检索范围只看牌局）：先看这一帧**报告里有没有可选策略** —— 报告给这一帧的决策者列出的可选策略不止「过」（`0.0%` 的吃 / 碰 / 杠选项也算「列出来了」）才是「面板有内容」，面板一定会给出 AI 分析结果（当前决策 + 表格 + 5 项数据）；然后这一列再按 **10% 门槛**筛选，所以低概率的鸣牌选项不会单独列出来。候选写成 `打2m 60.0%`、`2p4p吃 45.0%`、`立直`、`PASS 100.0%` 这样；只要这一帧有立直选项，立直一定排在第一行；概率统一保留一位小数；`其它` = `100.0%` − 表内已显示选项的**显示值**合计（不足 0.1% 不显示，所以表内合计总是 100.0%）—— 例：某张牌 99.54% 会显示成 `99.5%`，此时补一行 `其它 0.5%`。副露决策不适合用单条概率柱表示，所以只看这张表。新版 NAGA（`NAGA-避四` / `NAGA-争一`）的决策是「打哪张牌 × 是否立直」的**联合分布**：这一列会直接列出 `打2m 60.0%`（默听打）与 `打3p立直 36.2%`（立直打），并且**不再单独列「立直」一行**（旧模型仍是「打牌分布 + 单独立直」的边缘分布展示，保持不变）。新版 NAGA 的报告还在同一帧里给出**完整动作空间的其它动作**：摸牌帧的**自摸**（`hora`）、**九種九牌流局**（`kyushu`）、逐个可杠牌的**暗杠 / 加杠**（`ankan_pai` / `kakan_pai`，报告直接给出杠哪张牌，可同时多张），鸣牌响应帧的**荣和**（`hora`） —— 这些项与打牌共用 10% 门槛，低概率的进 `其它`（用户 m10081）。
- **底部五项**：流局率、横移率、放铳率、和了率、期待顺位。

### 5.5 当前帧特征 / 局面

右侧「当前帧特征」面板列出这一帧的全部一、二类特征与取值（检索用到的特征会高亮）。没有打点行的帧会提示原因。

面板底部用大字显示这一帧的**局面**：

- **出牌局面**：轮到自己决定打哪张牌。
- **鸣牌响应局面**：别家打出的牌可能被鸣，自己需要决定吃 / 碰 / 杠 / 过。

### 5.6 事件列表

最右侧的事件列表按顺序列出本局全部事件（摸牌 / 打牌 / 鸣牌 / 立直 / 和了 / 流局…），点击可以跳到对应帧。

## 6. 牌谱分析（写入数据库）

1. 选择**新建数据库**（默认名 `paipu`，文件为 `data/db/paipu.sqlite`）或**扩充现有数据库**（追加进已有的库，库里已存在的牌谱自动跳过）。
2. 选择来源：**牌谱目录**（递归扫描该子目录）或**单个牌谱文件**；点「扫描」「全选 / 全不选」调整范围。
3. 可选勾选「同时写入原始数据（--full）」：把每一帧的手牌 / 副露 / 宝牌 / 分数一起写进数据库，以后新增特征时能直接重算；不勾选数据库约为一半大小。
4. 点「开始分析并入库」。进度条显示当前文件与已完成帧数。

打点对象就是第 3 节的三类决策帧，每行 42 个特征（取值见第 9 节）。速度参考：每帧约 0.1 秒，一份 12 局牌谱约 600 帧、约 1 分钟。

页面下方列出 `data/db` 里的全部数据库，可「设为当前库」（作为牌谱检索的默认库）或「删除」。

## 7. 牌谱检索

1. 选择**本地数据库文件**（或直接填路径）。
2. **是否具有AI决策**：四种互斥方案 —— 任意AI决策 / NAGA决策 / Mortal决策 / 同时具有（勾选多个第零类特征，全部满足）。不选择 = 不筛选。第零类是**按帧判定**的：同一份牌谱里有的帧命中、有的不命中。
3. **出牌 / 鸣牌响应**：必选单选，默认「出牌」。选「出牌」只检索出牌局面，「鸣牌响应」只检索鸣牌响应局面。
4. **牌谱特征**：逐条添加可填取值的特征（34 项 = 17 个第一类 + 17 个第二类，见第 9 节），每条都要填条件：
   - 枚举：下拉选择；
   - 整数：`3`、`1-5`、`1,3,5`、`>=2`；
   - 实数（期望枚数 / 期望打点）：`0.5`、`0-1.5`、`0,1,2.5`、`>=3`。
5. 点「检索」返回**同时满足全部条件**的打点帧。条目名 = 特征码 + 局况 + 本场 + 巡目 + 风位；点击进入静态帧查看（此时固定为那一行的视角，用「上一条目 / 下一条目」在结果间切换）。
6. 结果**分段载入**：一次取 1000 条，走到段尾时自动取下一段，结果框显示「第 A ~ B 条（共 T 条）」。
6. 「全部浏览」不设条件，按顺序阅览整库。

## 8. 本地数据管理

管理本机的用户数据目录：新建目录、把选中的条目移动到子目录或上一级、删除文件、删除子目录（会连同里面的内容）。牌谱在 `data/paipu/`，数据库在 `data/db/`。删除不可撤销。

## 9. 42 个特征词典

42 个特征 = 第零类 7 个 + 第一类 17 个 + 第二类 17 个 + 第三类 1 个。播放界面与检索条件里「可填取值」的第一、二类共 34 项。

### 9.1 第零类：AI 分析模型（7 个，按帧判定）

逐个打点帧判定「这一帧能不能用上某款 AI 模型的决策数据」：取值「是」当且仅当**这一帧做决策的那名玩家**带该模型的决策概率表。天凤牌谱七项都是「否」。

| 特征名 | 取值 |
| --- | --- |
| NAGA-平衡 分析 | 是 / 否 |
| NAGA-超副露 分析 | 是 / 否 |
| NAGA-避四 分析 | 是 / 否 |
| NAGA-争一 分析 | 是 / 否 |
| Mortal-4.1-避四 分析 | 是 / 否 |
| Mortal-4.1-平衡 分析 | 是 / 否 |
| Mortal-4.1-争一 分析 | 是 / 否 |

第零类不通过「添加特征词条」检索，改用第 7 节的四种方案。

### 9.2 第一类：逐帧局势（17 个）

| 特征名 | 取值 |
| --- | --- |
| 局况 | 東一局 … 北四局（16 种） |
| 是否南三局及以后 | 是 / 否 |
| 巡目 | 1 ~ 30（按「出牌」计） |
| 供托 | 0 ~ 30000（立直棒 ×1000 + 本场 ×300） |
| 自家 | 亲家 / 子家 |
| 顺位 | 1 ~ 4（同分按自风） |
| 自家立直状态 | 是 / 否 |
| 自家副露状态 | 是 / 否 |
| 自家副露数量 | 0 ~ 4（吃 / 碰 / 加杠 / 大明杠 / 暗杠的组数，拔北不算） |
| 立直家（他家）数量 | 0 ~ 3 |
| 立直家（他家）一发巡 | 是 / 否（另外三家里只要有一家处于「一发」就是「是」） |
| 副露家（他家）数量 | 0 ~ 3 |
| 两副露以上（他家）数量 | 0 ~ 3 |
| 三副露以上（他家）数量 | 0 ~ 3 |
| 亲家（他家）立直状态 | 是 / 否 |
| 亲家（他家）副露状态 | 是 / 否 |
| 亲家（他家）副露数量 | 0 ~ 4 |

「一发」= 某人立直宣言之后、到他下一次出牌（或他家鸣牌 / 各种杠）之前。

### 9.3 第二类：需要算法（17 个）

**三种向听数**（`-1` / `0` / `1` / `2` / `>=3`）：为达到听牌最少还要摸进或副露的牌张数；计算时扣掉场上已经看得见的牌。

| 特征名 | 取值 |
| --- | --- |
| 国士無双向听数 | >=3 / 2 / 1 / 0 / -1 |
| 七対子向听数 | >=3 / 2 / 1 / 0 / -1 |
| 面子手向听数 | >=3 / 2 / 1 / 0 / -1 |

**六个期望听牌枚数**：「期望枚数」= 在「达到听牌」的前提下，能达成满足起和役的和牌的牌张数期望；「绝对枚数」不看场上可见牌。带「副露」字样四项按副露状态计算；「立直 / 默听」两项对门清帧计算，副露帧为 0。

| 特征名 | 取值 |
| --- | --- |
| 副露自摸期望听牌枚数 | 实数 |
| 副露自摸期望听牌绝对枚数 | 实数 |
| 副露荣和期望听牌枚数 | 实数 |
| 副露荣和期望听牌绝对枚数 | 实数 |
| 立直/默听期望听牌枚数 | 实数 |
| 立直/默听期望听牌绝对枚数 | 实数 |

**六个期望打点**（含本场 / 供托 / 宝牌，按天凤段位战规则）：「立直」= 假想保持门清到听牌并宣布立直；「默听」= 假想不宣布立直；副露帧的立直项为 0；已和牌的帧记实际和牌得点。

| 特征名 | 取值 |
| --- | --- |
| 副露荣和期望打点 | 实数 |
| 副露自摸期望打点 | 实数 |
| 立直荣和期望打点 | 实数 |
| 立直自摸期望打点 | 实数 |
| 默听荣和期望打点 | 实数 |
| 默听自摸期望打点 | 实数 |

**两个危险特征**（以当前决策者为主视角；其他家无人立直时为 `-1`）：

| 特征名 | 取值 |
| --- | --- |
| 立直家（他家）危险筋组数量 | 0 ~ 18 |
| 立直家（他家）危险两面组数 | 0 ~ 288 |

### 9.4 第三类：局面（1 个）

| 特征 | 取值 | 说明 |
| --- | --- | --- |
| 等待鸣牌 | 是 / 否 | 「是」= 这一帧是**鸣牌响应帧**：有人打出一张**可能被他家鸣牌**的牌，可能鸣牌的那一家各占 1 行；其余帧都是「否」 |

判据看的是**是否可能被他家鸣牌**（而不是牌谱里实际有没有出现鸣牌）：

- 碰 / 大明杠：另外三家里有未立直的一家手里有同种 ≥ 2 张；
- 吃：只有出牌者的下家能吃，且当下家鸣牌后会因「禁止食替」无牌可打时，视为不能吃；
- 已经立直的家不能鸣牌；
- 仅可能被荣和（没人可能鸣牌）的出牌帧不算决策帧；暗杠 / 加杠 / 大明杠的展示帧、自摸帧都不算。

这一项不出现在检索的特征下拉里，也不列进「当前帧特征」面板（那一列由面板底部的大字「出牌局面 / 鸣牌响应局面」体现）。

## 10. 数据库与文件

- 数据库：`data/db/<名字>.sqlite`（SQLite）。一张 `frame` 表一行 = 一个打点帧，含定位信息（特征码、局、巡目、风位、顺位、供托…）、42 个特征列与条目名；勾选 `--full` 时另有一张 `frame_full` 表保存原始数据。
- 数据库里记录了生成它的软件版本。**大版本 + 中版本相同的库可以直接继续扩充 / 检索**（补丁版本不同不影响，例如 v1.3.1 能读 v1.3.0 的库）；结构版本不同、或大/中版本不同，才会提示「数据库版本不兼容」，需要重新分析。当前数据结构版本为 11，此后**不改数据库结构的更新只提小版本号**。
- 牌谱文件：`data/paipu/<子目录>/` 下，文件名 = 特征码 + 后缀（`.tenhou` / `.naga` / `.mortal-a|b|c`）。
- 扩充数据库时，库里已有相同特征码的牌谱会被自动跳过。

## 11. 命令行速查

分析、检索、服务也可以用命令行完成（`tools/analyze.py`）：

```powershell
# 分析：牌谱文件或目录（可多个）
python tools\analyze.py data\paipu\20261013-005531 --db-name demo

# 扩充现有库，并同时写入原始数据
python tools\analyze.py data\paipu\新的一批 --db-name demo --extend --full

# 打印 42 个特征定义 / 某个特征的取值分布
python tools\analyze.py --features
python tools\analyze.py --values junme --db-name demo

# 检索（每行一条「特征名=条件」）
echo 巡目=3,供托>=1000,自家立直状态=否 | python tools\analyze.py --query --db-name demo

# 按 AI 决策方案检索；第三类局面单选
python tools\analyze.py --query --ai naga --wait 鸣牌响应 --db-name demo

# 列出 / 删除数据库，导出 JSON
python tools\analyze.py --list-dbs
python tools\analyze.py --delete-db demo
python tools\analyze.py --export out.json --db-name demo

# 启动服务（等同 python server.py）
python tools\analyze.py --serve --port 8770
```

## 12. 常见问题

**Q：提示「数据库版本不兼容」怎么办？**
库的结构版本、或大/中版本与当前软件不一致（只有大版本 + 中版本相同的库能用），重新分析一遍即可。

**Q：分析很慢？**
每帧约 0.1 秒，其中大部分时间花在第二类特征（向听搜索）。一份 12 局牌谱约 600 个打点帧、约 1 分钟。有 `node.exe` 时会更快。

**Q：没有装 Node.js 能用吗？**
能。全部特征由 Python 计算，只是稍慢。

**Q：端口被占用 / 想换端口？**
`python server.py --port 9000`，然后用打印出的新地址访问。

**Q：天凤牌谱为什么没有 AI 决策？**
天凤牌谱本身不含 AI 数据，所以第零类特征全是「否」，播放界面的 AI 决策栏留空。

**Q：下载完牌谱，分析页看不到它？**
分析页的目录下拉只列 `data/paipu` 下的内容；点「扫描」刷新，或直接用「牌谱下载」页（下载完会自动跟到该目录）。

**Q：安装包版和源码版的数据是同一份吗？**
不是。安装包版用 `%LOCALAPPDATA%\tenhou-paipu-analysis\`，源码版用项目根目录的 `data\`。
